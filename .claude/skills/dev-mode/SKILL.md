# 開発モード

このリポジトリの開発サーバー（`npm run dev` / Next.js）を立ち上げ、
ブラウザで変更を確認できる状態にするための手順。

## 起動

1. 状況を伝える。

   ```bash
   .claude/hooks/jarvis-say.sh "開発モードを起動しています"
   ```

2. 依存が入っていなければ入れる。`node_modules` が無いときだけ。

   ```bash
   [ -d node_modules ] || npm install
   ```

3. 開発サーバーを起動する。**Bash ツールの `run_in_background: true` で実行する**
   （フォアグラウンドで実行するとセッションが固まる）。

   ```bash
   npm run dev
   ```

   `predev` で `scripts/copy-tesseract-assets.mjs` と `scripts/fetch-fonts.mjs` が先に走る。
   `fetch-fonts.mjs` はネットワークを使うので、オフライン環境では失敗することがある。
   その場合はフォントが無いだけで開発サーバー自体は動くため、失敗をそのまま伝えて先に進む。

4. 出力に `Ready in` または `Local:` が出るまで待ち、実際に表示された URL を読み取る。
   ふつうは <http://localhost:3000> だが、3000 番が埋まっていると Next.js は
   自動で別のポートを使うので、**ログに出た URL をそのまま伝えること**。

5. 起動できたことをユーザーに伝える。URL・ポート・停止方法をセットで書く。

## 停止

まず、起動時に使ったバックグラウンドタスクを止める（これが一番確実）。

タスク ID が分からなくなっていたら、**ポートを握っているプロセスを狙って止める**。

```bash
lsof -ti tcp:3000 | xargs -r kill    # 3000 は実際に使っているポートに置き換える
```

`pkill -f "next dev"` のような名前での一括終了は使わないこと。`-f` は
コマンドライン全体を見るので、**"next dev" という文字列をたまたま含んでいるだけの
シェルやログ出力用のコマンドまで巻き添えで終了させてしまう**（実際にこれで
実行中のシェルごと落ちたことがある）。ポート指定なら対象を取り違えない。

## 再起動

`next.config.ts` や依存関係を触ったときは、開発サーバーの再起動が要る。
停止 → 起動の順でやり直す。

## 注意

- このアプリは `output: "export"`（静的書き出し）の構成だが、開発中は `next dev` が
  ふつうにサーバーを立てるので、そのまま確認してよい。
- 本番相当の確認をしたいときは `npm run build` で `out/` を作り、
  `npx serve out` のような静的サーバーで開く。
- データは localStorage に入る。開発サーバーのポートが変わると別オリジン扱いになり、
  それまでの記録が見えなくなる。ポートが変わったときはその旨を伝える。
